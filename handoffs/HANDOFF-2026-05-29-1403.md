## Dead Ends — Do Not Retry

### Deploying a same-version fork build via uv
| Approach Tried | Why It Failed | Time |
|---|---|---|
| `uv tool install --force --from . "memsearch[onnx]"` | uv error: `--from` package requirement conflicts with the `memsearch[onnx]` install request | ~2 min |
| `uv tool install --force ".[onnx]"` (no `--no-cache`) | uv **reused a cached 0.4.5 wheel** (version unbumped) → silently installed STALE code; `--replace`/`watchlock.py` absent despite "Installed" success | ~10 min |
**What works**: `uv tool install --force --no-cache ".[onnx]"` (prints `Built memsearch @ file://…`). Or bump `pyproject.toml` version. **Always verify by content** (`memsearch watch --help \| grep -- --replace`), never by the "Installed" message.

### Refreshing one file in the global collection
| Approach Tried | Why It Failed | Time |
|---|---|---|
| `memsearch index "<single-file>" -c <collection>` (run repeatedly to "refresh" the lessons doc) | `MemSearch.index()` runs a deleted-file GC scoped to the scanned PATHS → it **deleted every other file's chunks**. Pruned the collection 4748→2101 (real data loss; `stats` row_count masked it by staying high on tombstones) | ~caused the whole data-loss detour |
**What works**: full-tree `memsearch index "<memory-dir>"` (idempotent, non-destructive) or let the watcher index. Source markdown is the truth, so a full re-index restores pruned chunks.

### Diagnosing the chunk-count drop
| Approach Tried | Why It Failed | Time |
|---|---|---|
| Asserted "compaction made tombstones invisible / no data loss / true count ~2101" | Wrong — Milvus applies deletes via a query-time bitmap, so a distinct-key query is always truthful; the drop was **real deletion**, not a view artifact. True count is ~4748 | ~corrected after advisor pushback |

### git stash with the stray `NUL` file present
| Approach Tried | Why It Failed | Time |
|---|---|---|
| `git stash push -u` | A reserved-name `NUL` file (untracked) blocked git's working-tree reset → stash left cli.py un-reverted while removing `watchlock.py`; broke the comparison | ~5 min |
**What works**: tracked-only stash (`git stash push <files>`) avoids untracked `NUL`; or remove `NUL` first via `Remove-Item -LiteralPath '\\?\D:\...\NUL' -Force`.

### Lock design — shared key (first cut)
Sharing one lock key between `watch` and `index` made a manual `index` refuse while a watcher held the collection (blocked a legit workflow). **Fixed**: split to `(domain, collection)` keys — `watch` and `index` serialize within their own kind, never cross-block.

### Tombstone reclamation
`memsearch compact` is NOT Milvus compaction — it's LLM memory summarization (destructive to raw chunks). Use `pymilvus client.compact(collection)` (or Milvus's automatic background compaction).

## Key Decisions
- **OS advisory lock over PID-file liveness**: kernel releases on death, so "lock held" == "live writer" — eliminates PID-reuse kill hazard and stale-file/TOCTOU. Trade-off: PID sidecar still needed for `--replace` to know whom to kill (read only when lock confirmed held → safe).
- **`(domain, collection)` lock key**: `watch`/`index` serialize within kind without cross-blocking. Trade-off: a watcher + a divergent-model `index --force` can still dup — restart the watcher instead.
- **Retire `kill_orphaned_index`, keep `kill_orphaned_milvus_lite`**: the index-process sweep is now redundant (lock + `--replace`) and was a Windows no-op anyway; the milvus_lite GC is Lite/POSIX-only and load-bearing (frees the `.db` file lock) so it stays.
- **Fork deploys locally, not to PyPI**: `memsearch` PyPI name belongs to upstream (zilliztech); deploy via `uv tool install` from the local path.
- **Docs live in `CLAUDE.md`** (canonical) with `AGENT.md`/`MEMORY.md`/`AGENTS.md` as symlinks; `AGENTS.md` (plural) added for cross-tool standard.
